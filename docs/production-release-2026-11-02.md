## 耗时诊断与本轮优化

三轮整流程分别约 72 / 91 / 95 秒，包含规划、图片任务与独立质检；质检前已经保存作品。按已持久化事件计算，首图保存分别约 57 / 73 / 77 秒。规划模型请求分别约 14.5 / 20.9 / 20.5 秒，独立质检阶段约 14–17 秒。

ModelJetty 原图任务日志显示排队均不足 0.3 秒，从受理到结果可读约 14 / 26 / 27 秒。因此整轮 Agent 时间不能当作图像模型的推理时间；异步编排和队列轮询也存在额外耗时。

- 等待图片子任务时只读检查状态，避免每 3 秒解密凭据和重复写整份 run。
- 图片任务完成主动唤醒父 Agent；保留持久化监控和 cron 恢复。
- Queue 每次交付最多进行 6 次只读结果查询（默认间隔 3 秒，约 15 秒窗口），减少重复排队、凭据读取和状态写入；付费创建请求仍只提交一次。
- 移除部分冗余 run 保存，保留付费意图、规划结果、结果展示和质检意图的持久化边界。
- 规划提示要求每张图片提示词只在 actions 中输出一次；兼容的顶层 prompt 由主机补齐。生图卡开启 Agent 且附带参考图时，将看图和规划合并为一次调用。
- 新 run 记录首图保存和独立质检耗时；执行记录明确显示“全流程”，质检期间图片可查看和下载。

直接生图与优化后 Agent 的新样本对照结果将在生产回读后追加；单个样本不能代表稳定 SLA。静态资源压缩不作为生图推理提速证据。
