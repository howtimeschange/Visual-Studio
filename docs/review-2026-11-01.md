## 审查发现与修复（按优先级）

### P1：匿名项目列表可枚举账号项目及其 metadata

**已修复**：项目列表/创建要求登录，只按账号 owner/member 查询；输入 sessionId 不改变可访问范围。素材、作业和对话读取统一拒绝匿名及非归属账号。

位置：`functions/api/canvas/projects.ts:9`、`functions/_lib/v2-store.ts:1488`。

未登录请求走 `listCanvasProjects(env, sessionId)`；不传 sessionId 会查询全部 canvas_projects，传任意 sessionId 也未验证其归属。返回包含 ownerUserId 和 metadataJson；metadata 可能含 AI 会话内容。项目详情上的权限检查无法保护这个列表响应。

**已在隔离本地 D1 + HTTP 复现**：本地注册测试用户，创建其账号项目，再以无 Cookie 的客户端 GET `/api/canvas/projects`，HTTP 200 且返回该用户项目。没有读取生产项目。

建议：列表要求登录，仅返回 owner/member 可访问的项目。若保留匿名草稿，使用服务端签发的匿名 session cookie，并只列出该会话的无 owner 项目；不能信任 query 中的 sessionId。加匿名、其他账号、viewer/editor 的负向回归。

### P1：未验证邮箱可命中管理员邮箱白名单

**已修复**：管理员只由 `ADMIN_USER_IDS` / `VS_ADMIN_USER_IDS` 授权，邮箱白名单停止授予权限。部署前需将现有管理员配置迁到用户 ID。

位置：`functions/_lib/auth.ts:145`、`functions/api/auth/register.ts:16`、`functions/_lib/admin.ts:12`。

注册只校验邮箱格式与密码长度，直接登录；`isAdminUser` 又仅比较邮箱字符串与 ADMIN_EMAILS/VS_ADMIN_EMAILS。若管理员白名单邮箱尚未注册，攻击者可先注册该地址获取管理权限。是否当前生产存在这样的邮箱未检查；这是配置满足时可触发的源码缺陷。

建议：在邮箱验证完成前禁止基于邮箱授予管理员权限，短期改用受控的 ADMIN_USER_IDS。ModelJetty 新增身份不按外部邮箱合并或赋予本地管理员权限，避免扩大这一缺口。

### P1：模型输入素材读取缺少一致的资源权限校验

**已修复**：所有引用素材在提交前校验，runner 按固定 owner 再次校验；共享素材需真实项目成员权限和结构化 element 引用。写入 element 也验证素材访问，不能植入其他账号 assetId 来自授访问。Canvas Agent 强制登录。

位置：`functions/api/canvas/psd-ocr.ts:695`、`functions/api/generate-direct.ts:235`、`functions/api/canvas/agent.ts:424`。

这些执行路径直接按 assetId 读取素材，未先校验 userId 或合法共享项目引用。素材下载路由的权限校验不能代替模型输入路径的校验；持有别人的 assetId 时可将其图片送入模型分析/生成。Canvas Agent 主路由还使用可空 getAuthContext，配置服务端 Vision Key 时匿名请求可能调用付费文本模型。

建议：统一 asset/conversation/job 访问断言，所有模型输入在排队前校验，执行时再次按固定作业 owner 校验；共享输入需要真实项目成员权限及明确的素材引用。Canvas Agent 的付费路径要求登录。

### P1：任务受理后、回执写入前崩溃仍可能重复生图

**已修复自动重发风险**：外部调用前持久化提交意图，使用 item ID 作为稳定 `X-Request-Id`，创建后立即持久化回执。没有回执的中断 running item 标为 `UNKNOWN_SUBMIT_RESULT`，恢复和手动重试均禁止重发；已有回执只恢复 GET 查询。ModelJetty 配合端提供持久化防重及按 request ID 的只读回查。缺少身份的 1xm 未知请求仍需人工核对，不宣称跨系统 exactly-once。

位置：`functions/_lib/v2-runner.ts:2504`。

`recoverRunningJob` 对没有 imageTask 的过期 running item，在未耗尽次数时重新入队。如果进程正好在上游已接受请求但本地未保存回执时退出，恢复程序无法区分“尚未提交”和“已提交未记账”，下一次可能再发 POST。后续修复已消除自动重发窗口：保存提交意图/稳定请求 ID，丢失回执则停止重发，保留人工回查边界。

建议：在外部调用前持久化 submit intent/稳定 request ID；服务商提供幂等创建或按 request ID 查询。缺少可查询身份的已提交不明项应进入人工核对状态，不能自动重发。取消本地任务不等于供应商取消或退款。

### P2：session 归属可被后续请求改写

**已修复**：已有 session 的归属不可覆盖，账号不匹配时新建 session；登录/注册不再凭浏览器给定的 sessionId 认领旧匿名资源。旧匿名数据不自动归属任何账号。

位置：`functions/_lib/v2-store.ts:836`。

`ensureSession` 接收浏览器传来的 sessionId，对已存在会话使用当前 userId 覆盖原归属；内存实现行为相同。账号切换或其他用户获得 sessionId 后会造成会话归属错误，且匿名资源认领也只依赖客户端传来的 ID。

建议：绑定后的 userId 不允许被其他账号覆盖；换账号新建 session。匿名 session 由服务端 cookie 证明持有，认领必须验证这一凭证。

### P2：翻译任务与 HTTP body 仍有长占用窗口

**已修复**：翻译切换到创建/查询 task-step，创建即保存任务 ID，分次 Queue 执行；轮询不重复 OCR。共享 fetch deadline 延续到 body 读取，并设置响应大小上限。挂起 body 回归验证创建只发生一次且按时结束。

位置：`functions/_lib/v2-runner.ts:686`、`functions/_shared.ts:970`。

翻译 runner 仍在一次执行中通过 `executeTranslate` 等待图片任务，而换装/直接生成已经能分步保存回执、跨队列执行。`fetchWithTimeout` 在响应头返回后就清除定时器，后续 `response.text()` / `arrayBuffer()` 不受该超时完整覆盖。慢上游和慢图片 body 会延长 Worker 占用与恢复窗口。

建议：将翻译也改为创建即保存回执的 task-step；把 deadline 延续到 body 读取/结果下载，并限制响应体大小。需要覆盖“响应头已到、body 挂起”的回归。

## 真实联调追加修复

- Workers 不支持 `redirect: error`：认证请求改用 `manual` 并拒绝非成功响应，保持不跟随重定向、不外传凭据。
- OIDC 显式请求 `prompt=consent`，缺少 refresh token 则拒绝完成连接，避免十分钟后才暴露缺失。真实轮换通过运行中的 Worker 验证。
- 画布保存已受理 job ID，失败/重载后可继续读取同一任务；认证失败保留加密连接标记。旧任务仅能凭同账号、固定 managed origin 的已存回执恢复连接。
- ModelJetty unknown 状态停止轮询并拦截重试；JPEG `b64_json` 按真实签名识别 MIME、读取尺寸，下载扩展名匹配 MIME。

本次检查范围内没有保留未修复的上述六项发现。生产开放仍需专用 client、域名、迁移和部署的独立验收。
